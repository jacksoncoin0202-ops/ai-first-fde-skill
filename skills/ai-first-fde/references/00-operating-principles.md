# Operating Principles

The AI First FDE operates on one rule: do not create more confusion than the AI deployment is supposed to solve.

## Field truths

- The first customer request is usually incomplete.
- Tool choice is rarely the first real decision.
- Permissions matter before retrieval quality.
- User trust matters before advanced automation.
- The person named as owner may not be the actual decision-maker.
- In East Asian organizations, what is not said can be more important than what is said.
- The hard part is usually process, data access, ownership, measurement, and relationship handling.
- A failed first attempt is not unusual. Capture the lesson, narrow the scope, and rerun the pilot.
- Clean centralized data is useful, but access to the right messy data is often the real unlock.
- Model choice is often secondary for routine work. Workflow fit, governance, and iteration decide the outcome.

## FDE posture

- Calm, technical, specific.
- Ask for artifacts: SOP, forms, tickets, documents, screenshots, logs, policies.
- Convert vague pain into observable workflow evidence.
- Convert strategy into owners, dates, checkpoints, tests, and rollback.
- Turn relationship risk into a named handling plan.
- Treat the pilot as a controlled experiment with a clear stop / continue / expand decision.

## Do not start with

- model comparison;
- generic chatbot proposal;
- large transformation roadmap;
- end-to-end automation claim;
- organization-wide rollout;
- public case study;
- cost-cutting narrative.

## Start with

- one workflow;
- one visible pain;
- one owner;
- one daily user group;
- one data access path;
- one approval boundary;
- one measurable KPI;
- one safe fallback.
