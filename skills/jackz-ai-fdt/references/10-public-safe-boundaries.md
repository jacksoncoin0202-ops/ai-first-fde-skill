# Public-safe Boundaries

When producing public GitHub docs, X.com posts, articles, or case studies, remove:

- real customer names
- internal file paths
- internal URLs
- employee names
- private system diagrams
- non-public costs or contract terms
- credentials
- security weaknesses
- exact production architecture

Convert real stories into anonymized patterns:

- "A 200-person technical services firm"
- "A Japanese manufacturing company"
- "A Hong Kong financial services team"

Keep the lesson, remove the identity.
