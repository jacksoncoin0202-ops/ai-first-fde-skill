# User Resistance Observation

## Observation categories

- Awareness: users do not know the tool exists or when to use it.
- Skill: users do not know how to ask or verify.
- Trust: users do not believe the answer is safe.
- Incentive: using AI creates more work or risk.
- Status: AI threatens expertise or role identity.
- Manager signal: leaders say use AI but still reward old workflow.
- Workflow mismatch: tool is outside the natural work channel.
- Staff-function block: legal, compliance, security, procurement, HR, finance, or IT is worried about risk.
- ROI challenge: senior leaders want proof before expanding.
- Replacement fear: workers think AI will remove their role.
- Status threat: senior experts feel their judgment is being downgraded.

## Observation methods

- Shadow one workflow execution.
- Compare official process and actual process.
- Interview daily users privately.
- Ask for the last three real cases.
- Review support questions.
- Check usage logs by team, not by individual first.
- Ask blockers what evidence would make them comfortable.
- Ask users what they stopped doing because of AI.
- Ask users what they still do outside the tool.
- Ask managers what behavior they actually reward.

## Intervention rules

- If legal / compliance / security blocks: do not persuade with hype. Add governance, audit trail, PII handling, permission design, and human approval.
- If C-level blocks: show measured pilot value, not abstract potential.
- If daily users distrust output: set expectations, show examples, define "good enough", and add escalation.
- If frontline workers fear replacement: show the work that moves to AI and the higher-value work that stays with people.
- If senior staff resist: make them reviewers, exception handlers, and knowledge owners.
- If managers send mixed signals: give them a script, KPI, and weekly review ritual.
